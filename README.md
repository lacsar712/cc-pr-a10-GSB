# 印刷套准复核台

接口只把印张偏差放进待处理队列。另一个进程用行锁领走一条，算出套准或套不准后再写回。页面每隔一秒看一次，直到结论出现。

领取有超时回收：任务落在领取态超过设定秒数仍未写出结论，会被自动退回待处理供再次领取，并记入回收流水。超时秒数以领取那一刻的快照为准，改秒数只约束此后新落入领取态的任务。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3194 |
| 接口 | http://localhost:8194 |
| PostgreSQL | localhost:54394 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| printer | print123456 | 可送复核、可改超时秒数 |
| checker | check123456 | 只看（含超时设置与回收流水），改不了秒数 |

## 启动

```bash
cd projects/15-print-register-review
docker compose up --build
```

## 领取超时页

导航栏「领取超时」页含三块：

- **超时秒数设置**：印刷员可改并保存；只读账号只能看。
- **领取中监视**：当前落在领取态的任务、已领取秒数与生效的超时秒数。
- **回收流水**：每次超时回收的时间、印张、领取时刻与当时生效的秒数。

相关接口：`GET/PUT /api/claim-timeout`（PUT 仅印刷员）、`GET /api/claiming`、`GET /api/reclaims`。

## 验收

1. printer 登录后稍等，封面-01 变成套准，内页-09 变成套不准。
2. 再送一条青偏差 0.5 的印张，状态先是待处理，随后变成套不准。
3. checker 没有送复核按钮，进「领取超时」页能看秒数与回收流水，但没有保存按钮（直接调 PUT 接口返 403）。
4. 领取超时回收：先让人为拖住领取——
   ```bash
   WORKER_HOLD_SECONDS=30 docker compose up -d --force-recreate worker
   ```
   再到「领取超时」页把秒数改成 2，回「复核台」送一条复核。任务先出现在「领取中监视」，约 2 秒后自动退回待处理，「回收流水」出现一条回收记录。把秒数改回大于拖住时长（如 60）后，任务在下一轮领取后正常出结论。
5. 改秒数只约束新领取：在任务已落入领取态后改小秒数，该任务仍按领取时的秒数判定回收。
6. 演示完恢复工人：
   ```bash
   docker compose up -d --force-recreate worker
   ```
