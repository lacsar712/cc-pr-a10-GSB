# 印刷套准复核台

接口只把印张偏差放进待处理队列。另一个进程用行锁领走一条，算出套准或套不准后再写回。页面每隔一秒看一次，直到结论出现。

领取心跳超时要回收：印刷员可设定超时秒数。任务一旦落在领取态且超过秒数仍未写出结论，就自动退回待处理供再次领取，并记一条回收流水。改秒数只约束此后新落入领取态的任务（领取时把秒数快照到任务上）。

## 验收

1. printer 登录后稍等，封面-01 变成套准，内页-09 变成套不准。
2. 再送一条青偏差 0.5 的印张，状态先是待处理，随后变成套不准。
3. checker 没有送复核按钮。
4. 顶部导航打开「领取超时」页：可设超时秒数、看到领取中监视（领取时刻与倒计时）和回收流水。
5. printer 把超时秒数改得很小（如 3 秒）保存，点「模拟拖住一条领取」：
   - 任务先出现在领取中监视并倒计时；
   - 倒计时归零后约 1 秒内自动退回待处理，随后被重新领取并写出结论；
   - 回收流水出现一条记录（印张、领取时刻、回收时刻、当时快照的秒数、第几次回收）。
6. 改成大秒数后再拖住，任务按领取时快照的小/大秒数计时——之后再改秒数不影响已在领取态的任务。
7. checker 登录打开「领取超时」页：只能看到当前秒数与流水，输入框与保存/模拟按钮不可用，直接调 `PUT /api/claim-timeout` 返回 403。

## 回收机制

- 每条任务在领取（pending → running）时把当前 `claim_timeout_seconds` 快照到 `jobs.timeout_seconds`，并记 `claimed_at`。
- worker 每秒执行一次回收扫描：对 `running` 且 `claimed_at + timeout_seconds ≤ now` 的任务加行锁（`FOR UPDATE SKIP LOCKED`，避开正被持锁处理的任务），退回 `pending`、`reclaim_count + 1`，并向 `reclaim_logs` 写流水。
- 退回待处理的任务按普通队列再次被领取；超时前已持锁的正常处理不受影响。
